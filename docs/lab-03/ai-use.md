# Lab 3 — AI Use and Reflection

**LLM/agent used:** Antigravity coding agent (Gemini 3.6 Flash / GLM) for code generation, with AI chatbot sessions for Playwright/Prisma troubleshooting. Sprint 3 was built issue-by-issue (Issues 1–9). Two notable mid-sprint **handovers** happened: the session implementing Issue 8 (Public Comments & Internal Notes) hit its limit mid-edit, and a fresh agent session completed the remaining UI panel, requester-side comments, and UI tests; then the session implementing Issue 9 (E2E Testing) hit its limit after writing the specs but before the suite was green, and a fresh session finished verification. A good handover prompt (completed work, remaining work, hard rules, exact verification commands) let each fresh session resume without redoing finished work.

## Reflection
Sprint 3 showed the value of strict, spec-first prompting: pasting the api-spec status-code table and the non-negotiable security rules directly into the prompt produced far fewer correction rounds than open-ended requests. The Issue 8 handover also proved that a good handover prompt (completed work, remaining work, hard rules, verification commands) lets a fresh agent resume safely — the recovery session validated the repair by re-running the whole test matrix rather than trusting the broken file. Finally, automating screenshots and safety-rule checks in Playwright turned the review checklist into something that runs on every command instead of relying on manual inspection. The Issue 9 takeover reinforced a second lesson: the fastest way to trust a half-finished suite is to run it, read the real failure output, and fix the cause (a strict-mode locator, the wrong admin endpoint, or a pagination assumption) rather than editing tests to match whatever the app happened to do — every change here kept the documented contract intact.
